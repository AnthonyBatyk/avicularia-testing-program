## 1. Призначення

Avicularia продовжує функціональність КБЖВ: блоки продуктів, калькулятор, архів днів і статистику, профілі, авторизацію, адміністративні інструменти, два синхронізовані відображення консолі, вкладку «Зручності». ## 3. «Тренування»: підтримуваний формат

Загальний вхідний ZIP-файл **містить шість JSON**, в корені або в одній спільній папці. Службові файли macOS ігноруються:

```text
00_manifest.json
01_profile.json
02_current_state.json
03_history.json
04_plan.json
05_completed_plan.json
```

- `00_manifest.json` описує формат `monderight-powerlifting-archive`, версію 1, SHA-256 інших JSON-файлів та їхні ролі.
- `01_profile.json` — профіль спортсмена, довгострокові налаштування.
- `02_current_state.json` — поточний стан.
- `03_history.json` — хронологія.
- `04_plan.json` — **тільки цей файл відображається як план**: дні, вправи, підходи, повторення, вага, примітки.
- `05_completed_plan.json` — довідкові дані щодо виконання за узгодженою схемою.

При завантаженні повного ZIP обов'язково звіряється контрольна сума SHA-256 кожного JSON із маніфестом. Початкові та версійні назви (`00_manifest_v1.json`, тощо) підтримуються. Оновлюючи JSON в іншому чаті, обов’язково перераховуйте SHA-256 у маніфесті. JSON-файли зберігаються у персональному сховищі користувача; без змін байти кожного файлу зберігаються. Підтримуються одночасне завантаження ZIP і окреме завантаження будь-якого JSON за канонічною або версійною назвою. За відсутності частини файлів їх можна додати окремо; ZIP-експорт можливий, лише коли всі шість наявні.

**Увага:** еталонний файл `04_plan.json` із переданого користувачем пакета має статус `example_not_for_execution`. Він є демонстрацією формату, а не тренувальною рекомендацією.

## 4. Кнопки та модальні вікна

Зверху вкладки три компактні кнопки, кожна відкриває окреме фіксоване вікно з кнопкою «Закрити»:

- **«Завантажити на сайт»**: «Завантажити ZIP на сайт» або шість індивідуальних дій.
- **«Вивантажити з сайту»**: «Вивантажити початковий ZIP» (сирі JSON), «Вивантажити виконаний ZIP» (копія з коментарями) або кожен JSON окремо.
- **«Очистити вкладку»**: видалити всі файли та коментарі разом або видалити один конкретний JSON; запитує підтвердження.

План відображається за днями. Для вправ показуються назва разом із приміткою і плашка «Підходи / Повторення / Вага»; вправи дня розділені лініями. Після дня є єдине поле коментаря: «Редагувати», «Очистити», «Скопіювати». Галочок виконання вправ немає. Коментар не змінює оригінальний `04_plan.json` до моменту формування виконаного ZIP.

## 5. Два види ZIP

1. **Початковий ZIP** містить шість збережених файлів архіву. Окремо збережені коментарі сайту не вбудовуються. За потреби контрольні суми маніфесту оновлюються до поточного стану JSON.
2. **Виконаний ZIP** містить ті самі шість JSON. У його `04_plan.json` додаються коментарі до відповідних днів, а `00_manifest.json` отримує правильні SHA-256 і `website_state` з версією, датою експорту та позначкою completed_extract. Це **не позначення фактичного виконання всіх вправ**: у файлі лише зафіксовані введені коментарі.

Кожна зміна вмісту / коментаря збільшує версію архіву. Формування виконаного ZIP також створює нову версію. Повторний імпорт ідентичного вмісту не збільшує номер. Дата останньої зміни та версія відображаються у плані та системній статистиці.

## 6. Збереження і синхронізація

Дані тренувань розділені за ідентифікатором авторизованого користувача. Вони зберігаються в локальній IndexedDB `avicularia_training_storage_v1` і в **окремій** D1 `avicularia-db` у таблиці `avicularia_archives`. Передача через `/avicularia/archive` вимагає сесії; Worker зберігає версії через ревізії для захисту від перезапису змін іншого пристрою.

У фоновому режимі стан перевіряється приблизно раз на 20 секунд і після дій; окремої кнопки синхронізації немає. За розбіжності пристроїв передбачено вибір локальної або серверної копії. Сайт має отримати актуальні дані після входу тим самим акаунтом на іншому пристрої. На відміну від окремого локального збереження, D1 дає змогу відновити дані між пристроями, але реальні резервні копії D1 все одно рекомендовані.

Архів тренувань **не включається до стандартного КБЖВ-експорту/імпорту**, оскільки має власний ZIP. Дії вкладки потрапляють у спільний журнал консолі. Для тренувань розділ «Стан системи» показує версію, дату та стан синхронізації.

## 7. Сторінка про назву
